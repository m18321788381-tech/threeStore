# 个人博客 · 云服务器部署文档

> 面向一台已购的公网云服务器（如阿里云 ECS / 腾讯云 CVM / 海外 VPS）。目标：用 Docker Compose 把博客跑起来，并配置域名 + HTTPS。

---

## 1. 前置条件

| 项目 | 建议 |
|---|---|
| 系统 | Ubuntu 22.04 / 24.04 LTS（本文以 Ubuntu 为例） |
| 配置 | 2 vCPU / 2 GB 内存起步（PostgreSQL + 6 容器足够） |
| 带宽 | 按访问量；个人博客 1–3 Mbps 即可 |
| 域名 | 一个已备案（国内）/ 已解析（海外）的域名，如 `blog.example.com` |
| 开放端口 | 安全组放行 `22`(SSH)、`80`、`443` |
| 软件 | 安装 Docker Engine + Docker Compose v2（非 snap 版） |
| 解析 | 域名 A 记录指向服务器公网 IP |

安装 Docker（Ubuntu）：
```bash
sudo apt update && sudo apt install -y docker.io docker-compose-plugin
sudo systemctl enable --now docker
# 可选：允许当前用户免 sudo 跑 docker
sudo usermod -aG docker $USER   # 重新登录后生效
```

---

## 2. 获取代码与配置

```bash
git clone <你的仓库地址> blog && cd blog
cp .env.example .env
```

编辑 `.env`，**至少修改以下项**（其余保持默认即可）：

| 变量 | 说明 | 建议值 |
|---|---|---|
| `SITE_URL` | 站点对外地址（RSS/OG/Sitemap 用） | `https://blog.example.com` |
| `SITE_TITLE` / `SITE_DESCRIPTION` / `SITE_AUTHOR` | 站点元信息 | 按实际 |
| `SECRET_KEY` | 应用密钥 | 用 `openssl rand -hex 32` 生成 |
| `JWT_SECRET` | JWT 签名密钥 | 同上，另生成一个 |
| `DB_PASSWORD` | PostgreSQL 密码 | 强随机串 |
| `ADMIN_USERNAME` / `ADMIN_PASSWORD` | 引导管理员账号 | **务必改掉默认 admin12345** |
| `CORS_ORIGINS` | 允许的跨域源 | 生产可设为 `https://blog.example.com` |
| `HTTP_PORT` | Nginx 对外 HTTP 端口 | `80` |

> 若启用 6 容器扩展，`REDIS_URL` 在 `docker-compose.redis.yml` 中已硬编码为 `redis://redis:6379/0`，无需在 `.env` 另设；空值表示不启用。

---

## 3. 部署方式一：4 容器（最简，推荐起步）

```bash
docker compose --env-file .env up -d --build
```

- 启动顺序：db → backend（自动 `alembic upgrade head`）→ frontend → nginx。
- 初始化管理员：
  ```bash
  docker compose exec backend python scripts/init_admin.py
  ```
- （可选）灌示例数据：
  ```bash
  docker compose exec backend python scripts/seed.py
  ```
- 浏览器访问 `http://<服务器IP>` 或你的域名（此时为 HTTP）。

---

## 4. 部署方式二：6 容器（含 Redis + Worker）

在方式一基础上叠加扩展文件：

```bash
docker compose -f docker-compose.yml -f docker-compose.redis.yml --env-file .env up -d --build
```

- 新增 `redis`（AOF 持久化）与 `worker`（后台预热 RSS/Sitemap 到 Redis）。
- 后端会经 `REDIS_URL` 使用缓存；不启用时自动降级为按需生成（见《架构设计文档》§4.3）。

## 5. 配置 HTTPS（Let's Encrypt 免费证书）

采用「先 HTTP 跑通 → certbot 签发 → 切 HTTPS」的流程。

### 5.1 准备目录并放通校验
```bash
mkdir -p nginx/certbot nginx/certs
# 确认 docker-compose.yml 的 nginx 已挂载 ./nginx/certbot 与 ./nginx/certs（默认已加）
docker compose up -d nginx      # 仅先起 nginx（80 端口 + 校验目录）
```

### 5.2 用 certbot 容器签发证书
```bash
docker run --rm \
  -v $PWD/nginx/certbot:/var/www/certbot \
  -v $PWD/nginx/certs:/etc/nginx/ssl \
  certbot/certbot certonly --webroot \
  --webroot-path /var/www/certbot \
  -d blog.example.com -d www.blog.example.com \
  --config-dir /etc/nginx/ssl --work-dir /tmp/certbot-work --logs-dir /tmp/certbot-logs \
  --email you@example.com --agree-tos --non-interactive
```
- 成功后证书位于 `nginx/certs/live/blog.example.com/{fullchain.pem,privkey.pem}`，已被挂载进 nginx 的 `/etc/nginx/ssl`。

### 5.3 启用 HTTPS 配置
```bash
# 用 HTTPS 模板替换默认配置（模板里把 yourdomain.com 改成真实域名）
sed 's/yourdomain.com/blog.example.com/g' nginx/ssl.conf.example > nginx/default.conf
# 放通 443：编辑 docker-compose.yml，取消 nginx 的 443 端口映射注释
#   - "${HTTPS_PORT:-443}:443"
docker compose --env-file .env up -d --build nginx
```
- 访问 `https://blog.example.com` 应自动跳转 HTTPS，浏览器锁标正常。

### 5.4 证书续期
Let's Encrypt 证书 90 天有效。加一条定时任务（crontab -e）：
```cron
0 3 * * 1 docker run --rm -v $PWD/nginx/certbot:/var/www/certbot -v $PWD/nginx/certs:/etc/nginx/ssl certbot/certbot renew --config-dir /etc/nginx/ssl --webroot --webroot-path /var/www/certbot && docker compose restart nginx
```

## 6. 媒体文件与持久化

- **数据库**：`POSTGRES_DATA` 命名卷，落盘于 `/var/lib/postgresql/data`。
- **媒体**：`media_data` 卷，backend 写入 `/app/media`，nginx 以 `/var/www/media` 静态托管 `/media/`。
- **备份**：
  ```bash
  # 数据库（逻辑备份）
  docker compose exec -T db pg_dump -U "$DB_USER" "$DB_NAME" > backup_$(date +%F).sql
  # 媒体卷
  docker run --rm -v blog_media_data:/data -v $PWD:/backup alpine tar czf /backup/media_$(date +%F).tar.gz -C /data .
  ```
- **恢复**：反向 `psql` 导入 SQL、`tar` 解回媒体卷即可。

## 7. 日常运维

| 操作 | 命令 |
|---|---|
| 看全部日志 | `docker compose --env-file .env logs -f` |
| 看某服务 | `docker compose logs -f backend` |
| 重启某服务 | `docker compose restart frontend` |
| 升级（拉新代码后） | `docker compose --env-file .env up -d --build` |
| 健康检查 | `curl -f http://localhost/health` 或后端 `/api/v1/health` |
| 进入容器排错 | `docker compose exec backend sh` |
| 停服（保数据） | `docker compose --env-file .env down` |
| 停服（清数据，危险） | `docker compose --env-file .env down -v` |

## 8. 常见问题排查

- **502 / 页面打不开**：先 `docker compose ps` 看各容器是否 `healthy`；`docker compose logs backend` 看是否迁移失败或连不上 db（确认 `DB_HOST=db`）。
- **媒体 404**：确认 `docker-compose.yml` 中 nginx 挂载的是 `/var/www/media`，且 `default.conf` 的 `alias /var/www/media/;`（已统一）。
- **HTTPS 证书不生效**：确认 `nginx/certs/live/<域名>/` 存在、`default.conf` 的域名与证书一致、443 端口已放开。
- **文章发布后 RSS 不更新（已用 Redis）**：worker 容器是否存活；手动触发 `docker compose exec backend python -c "import asyncio,sys; sys.path.insert(0,'scripts')"` 或重启 worker。
- **构建卡在删除文件**：仅本地开发机若出现批量删除被拦，属安全保护，非代码问题（CI/Docker 内无此限制）。
- **构建超时/长时间卡在 `[backend builder] RUN apt-get ...`**：境内直连 `deb.debian.org`、`pypi.org` 带宽极低（实测单步 1500s+）。现默认走 `mirrors.cloud.tencent.com`（`.env` 的 `APT_MIRROR_HOST` / `APK_MIRROR_HOST` / `PIP_INDEX_URL` / `NPM_REGISTRY`），且后端 builder 默认不装 gcc（`APT_BUILD_DEPS` 为空，依赖均有 cp312 预编译 wheel）。腾讯云 CVM 把 `APT_MIRROR_HOST`/`APK_MIRROR_HOST` 改成 `mirrors.tencentyun.com` 可走内网。
- **构建报 `error: can't find compiler executable` 或 sdist 编译失败**：临时 `docker compose --env-file .env build --build-arg "APT_BUILD_DEPS=build-essential libpq-dev" backend`，或在 `.env` 取消 `APT_BUILD_DEPS` 注释。
- **想看构建进度**：`docker compose --env-file .env build --progress=plain`，先单独构建再 `up -d`，避免 `up` 的进度条吞掉耗时细节。

## 9. 安全清单（上线前核对）

- [ ] `SECRET_KEY` / `JWT_SECRET` 已替换为强随机值
- [ ] `ADMIN_PASSWORD` 已改，且未使用默认 `admin12345`
- [ ] `DB_PASSWORD` 为强随机串
- [ ] 已启用 HTTPS，且 `SITE_URL` 为 `https://...`
- [ ] 安全组仅放行 22/80/443（后端 8000、DB 5432 不对外）
- [ ] `CORS_ORIGINS` 收紧到自有域名
- [ ] 服务器开启自动安全更新（`sudo apt install -y unattended-upgrades`）

---

## 10. 可选优化

- **对象存储**：媒体改存 S3/OSS/COS，替换 `MEDIA_ROOT` 与上传逻辑，便于多副本横向扩展。
- **CDN**：静态资源与媒体套 CDN，减轻源站压力。
- **监控**：接 Prometheus + node_exporter + Grafana，或云厂商 APM。
- **Redis 限流**：将 `app/core/rate_limit.py` 的内存实现替换为基于 `app/core/cache.py` 的 Redis 实现，支撑多副本。
- **自动备份**：用脚本 + cron 把数据库与媒体卷定期同步到对象存储/异地。

## 11. 一键速查（最小可行上线）

```bash
# 1) 准备
sudo apt install -y docker.io docker-compose-plugin
git clone <repo> blog && cd blog && cp .env.example .env
vim .env        # 改 SECRET_KEY/JWT_SECRET/DB_PASSWORD/ADMIN_PASSWORD/SITE_URL

# 2) 起服务（HTTP）
docker compose --env-file .env up -d --build
docker compose exec backend python scripts/init_admin.py

# 3) 上 HTTPS（见 §5）
mkdir -p nginx/certbot nginx/certs
# 签发证书 → 替换 default.conf → 放开 443 → 重启 nginx

# 4) 验收
curl -I https://blog.example.com
```
