# 个人博客 · 架构设计文档

> 配套《个人博客网站设计文档 v3.0》的实现层说明。本文描述**已落地**的技术架构、模块职责与关键设计决策，供后续维护、扩展与复盘使用。

---

## 1. 范围与目标

- 一个内容驱动的个人技术博客，支持文章管理、Markdown 渲染、标签/分类、评论、RSS/Sitemap、深色模式。
- 交付形态覆盖三种：浏览器访问（生产）、Web 部署（Docker 编排）、本地开发。
- 三项特色能力：**动态 OG 分享卡片、数字花园（双向链接）、Ctrl/⌘+K 终端彩蛋**。

非目标：多租户、付费订阅、复杂权限矩阵（当前仅「博主(admin) / 访客(reader)」两类角色）。

## 3. 系统架构

```
                       ┌─────────────────────────────┐
   浏览器 ──HTTPS──▶   │  Nginx ( :80 / :443 )        │
                       │  · TLS 终止 / 强制 HTTPS      │
                       │  · 静态资源长缓存             │
                       │  · /media /api 反代          │
                       │  · /feed.xml /sitemap.xml    │
                       └───────────┬───────────┬──────┘
                                   │ /         │ /api /media
                                   ▼           ▼
                        ┌────────────────┐  ┌────────────────┐
                        │ Frontend       │  │ Backend        │
                        │ Next.js :3000 │  │ FastAPI :8000  │
                        │ (standalone)  │  │                │
                        └───────┬────────┘  └───┬────────┬───┘
                                │ 模式A: SSR  │    │        │
                                │ 内网直连    │    │        │
                                │ INTERNAL_   │    │        │
                                │ API_URL     │    │        │
                                ▼            ▼    ▼        ▼
                          ┌──────────┐  ┌──────────┐  ┌──────────┐
                          │ PostgreSQL│  │  Redis   │  │  Worker  │
                          │  :5432   │  │  :6379   │  │(可选)    │
                          └──────────┘  └──────────┘  └──────────┘
                             数据卷        缓存/事件       SEO 缓存预热
```

- **Nginx** 是唯一对外入口；前端与后端只暴露内网端口，不直连公网。
- **媒体文件**：后端写入 `/app/media`（挂载为命名卷 `media_data`），Nginx 挂载同一卷于 `/var/www/media`，直接静态托管（`/media/`）。
- **Redis/Worker** 为可选扩展：不启用时，后端与前端照常运行，仅失去 SEO 缓存与独立预热进程。

## 4. 请求与数据流

### 4.1 渲染模式（设计文档 §5.4 模式 A）
- **服务端组件（SSR/ISR）**：在 Next.js 服务端直接用 `INTERNAL_API_URL`（默认 `http://backend:8000`）拉取数据，避免浏览器跨域，也不依赖运行期公网 DNS。
- **浏览器侧请求**：前端对 `/api`、`/media`、`/feed.xml`、`/sitemap.xml` 的请求由 `next.config.ts` 的 `rewrites` 在服务端转发到后端（同源，无需 CORS）。
- 因此生产环境 `CORS_ORIGINS` 可收紧为前端域名，甚至保持默认亦安全（后端不直接暴露公网）。

### 4.2 Markdown 渲染管线
- `content_md` 为**唯一真源**；保存（创建/更新/发布）时由 `app/services/markdown.py` 渲染为 `content_html` 并缓存到库（读取详情零渲染成本）。
- 渲染步骤：`markdown-it-py` 生成 HTML → `[[双向链接]]` 占位替换（避免被清洗器误删）→ Pygments 代码高亮 → `bleach` 按白名单清洗（标签/属性 + `rel="noopener"`）→ 注入 TOC。
- 详情页前端用 `react-markdown` 做**兜底**渲染（如后端 HTML 缺失时），但生产以服务端 `content_html` 为准。

### 4.3 SEO 产物（RSS / Sitemap）
- `/feed.xml`、`/sitemap.xml` 由后端动态生成。
- 启用 Redis 后：`app/services/seo.py` 优先读缓存；`scripts/worker.py` 周期性 + **事件驱动**（后端发文/改删后广播 `blog:seo:invalidate`）刷新缓存。
- 未启用 Redis：每次请求按需生成（逻辑不变，仅无缓存）。

## 5. 后端分层架构

```
app/
├── core/          配置与横切
│   ├── config.py         Settings（环境变量，含 REDIS_URL 等）
│   ├── security.py       JWT 签发/校验、bcrypt
│   ├── rate_limit.py     内存限流（可替换为 Redis 实现）
│   ├── enums.py          PostStatus / CommentStatus / UserRole
│   └── cache.py          Redis 客户端（可选，静默降级）
├── db/            session.py（engine / SessionLocal / get_db）
├── models/        User, Category, Tag, Post, Comment, PostLink, Media, PostStat
├── services/      markdown, slug, links(双向链接), comments, feed(seo), serializers
├── schemas/       Pydantic 入参/出参
├── api/v1/endpoints/  auth, posts, taxonomy, comments, search, stats, media, links, meta
└── main.py        应用装配（CORS、静态挂载、异常处理、路由注册）
```

- **入参校验**：`schemas/`；**出参序列化**：`services/serializers.py`（统一 `ApiEnvelope{code,data,message}`）。
- **依赖注入**：`api/deps.py` 提供 `Pagination`、`get_current_user`、`get_current_admin`、`optional_user`、`get_client_ip`。
- **迁移**：`alembic/`，镜像启动自动 `alembic upgrade head`。

## 6. 前端架构

```
src/
├── app/                  路由（App Router）
│   ├── layout.tsx        根布局：Metadata(OG/Twitter/RSS) + Providers + Header + Footer + TerminalEgg
│   ├── page.tsx          首页（ISR revalidate=60）
│   ├── posts/[slug]/     文章详情（SSR + generateMetadata 动态 OG + Article JSON-LD）
│   ├── categories / tags / archive / search / about / garden
│   ├── admin/(panel)/    后台（AuthGuard + 侧边栏）
│   ├── og/route.tsx      动态 OG 图（next/og ImageResponse）
│   ├── sitemap.ts / robots.ts
├── components/  layout / post / comment / garden / egg / admin / editor / common
├── lib/         api.ts(客户端) / utils.ts / site.ts(站点配置)
└── styles/      globals.css(设计系统) / pygments.css(代码高亮)
```

- **主题**：`next-themes`（class 策略），CSS 变量定义 light/dark。
- **数据获取**：服务端组件用 `lib/api.ts` 的 `serverGet`（失败返回 `null`，保证构建/渲染不崩）；客户端组件用 TanStack Query。
- **特色组件**：`garden/GraphCanvas`（d3-force 力导向图）、`egg/TerminalEgg`（全局快捷键终端）、`post/PostContent`（注入代码块复制条）。

## 7. 数据模型（核心表）

| 表 | 关键字段 | 说明 |
|---|---|---|
| users | id, username, display_name, password_hash, role | 管理员/访客 |
| categories | id, name, slug, parent_id | 支持层级（当前 UI 单级） |
| tags | id, name, slug | 标签 |
| posts | id, title, slug, summary, content_md, content_html, toc, status, view_count, published_at, author_id, category_id | 文章；`content_md` 真源 |
| post_tags | post_id, tag_id | 多对多 |
| comments | id, post_id, parent_id, author_name, content, status, is_pinned, ip_address | 树形（parent_id 自引用） |
| post_links | source_id, target_id | `[[双向链接]]` 关系 |
| media | id, filename, mime_type, size | 上传资源元数据 |
| post_stats | post_id, view_count | 浏览统计 |

外键级联：`post_links`、`comments` 随 `posts` 删除而清理。

## 8. 关键设计决策

1. **Markdown 服务端渲染 + 缓存**：写入期一次性渲染，读取零成本；避免 XSS 用 `bleach` 白名单。
2. **`[[双向链接]]` 落库**：`post_links` 表存关系，详情页算 outbound/backlinks，`/garden` 出图谱；发布/更新时 `sync_post_links` 重建。
3. **SEO 缓存可选化**：用 Redis 仅当 `REDIS_URL` 非空；否则按需生成，逻辑统一在 `seo.py`。
4. **限流可替换**：`rate_limit.py` 当前内存实现；集群部署可换 Redis（参考 `cache.py` 客户端）。
5. **安全基线**：JWT 双令牌、bcrypt、评论 bleach 清洗 + 敏感词/链接数/频率限制、媒体上传 MIME 白名单 + 魔数校验、CORS 可收紧。
6. **优雅降级**：Redis、Worker、OG 兜底图、API 失败返回 `null` —— 任意一环缺失都不致整体崩溃。
7. **配置即环境**：所有密钥/连接均从环境变量读取，绝不硬编码；`.env.example` 为模板。

## 9. API 设计

统一响应包：`{ code: int, data: T|null, message: string }`（`code=0` 表示成功）。

| 分组 | 路径前缀 | 鉴权 |
|---|---|---|
| 认证 | `/api/v1/auth` | 登录/刷新/me |
| 文章 | `/api/v1/posts` | 公开读；写需 admin |
| 分类 | `/api/v1/categories` | 公开读；写需 admin |
| 标签 | `/api/v1/tags` | 同上 |
| 评论 | `/api/v1/posts/{slug}/comments`、`/api/v1/comments`(admin) | 游客可发；审核需 admin |
| 搜索 | `/api/v1/search` | 公开 |
| 统计 | `/api/v1/stats` | 公开概览 / admin 明细 |
| 媒体 | `/api/v1/media` | 上传/管理需 admin |
| 链接 | `/api/v1/posts/{slug}/links`、`/api/v1/garden/graph` | 公开 |
| SEO | `/api/v1/feed.xml`、`/api/v1/sitemap.xml`、`/api/v1/health` | 公开 |

> 说明：本文中的 `/api/v1/feed.xml` 等是后端内部路由；经 Nginx/Next 反代后，浏览器访问的是同源 `/feed.xml`。

## 10. 特色功能实现

- **动态 OG 卡片**：`/og?title=&author=&tag=&template=&v=` 用 `next/og` 生成 1200×630 PNG；`v` 为内容指纹，变化即自动取新图；生成失败返回纯色兜底图，分享链路不中断。
- **数字花园**：正文 `[[标题]]` → 后端解析匹配 slug/title → `post_links` → 出链/反链；`/garden` 用 d3-force 渲染可缩放/拖拽/点选跳转的力导向图，未解析链接标灰。
- **终端彩蛋**：`TerminalEgg` 全局监听 Ctrl/⌘+K，命令白名单（`help/ls/cd/cat/open/theme/whoami/date/uname/sudo/clear/exit`），历史持久化，首次访问有提示气泡。

## 11. 容器化与编排

- **基础 4 容器**（默认 `docker-compose.yml`）：`nginx` + `frontend` + `backend` + `db`。
- **扩展 6 容器**（`docker-compose.redis.yml` 叠加）：追加 `redis` + `worker`。
  ```bash
  docker compose -f docker-compose.yml -f docker-compose.redis.yml --env-file .env up -d --build
  ```
- **镜像**：frontend 用 Next standalone 多阶段；backend 多阶段（builder 装依赖 → runtime 非 root + healthcheck）；nginx 官方镜像 + 自定义 `default.conf`。
- **数据持久化**：PostgreSQL 数据卷、媒体卷（`media_data`）被 backend 与 nginx 共享挂载。

---

## 12. 非功能特性

- **性能**：SSR/ISR + Markdown 预渲染 + 静态资源长缓存 +（可选）SEO 缓存；代码高亮服务端产出，前端仅做轻量增强。
- **安全**：见 §8.5；公网仅暴露 Nginx，后端/DB 不直连；HTTPS 由 `scripts/enable-https.sh` 一键启用（certbot + `nginx/ssl.conf.template`）。
- **可观测性**：各容器 healthcheck；后端 `/health`；`/api/v1/stats` 概览。
- **可扩展性**：`rate_limit`、`seo` 缓存、媒体存储均预留替换点（对象存储、Redis 限流、CDN）。
- **可维护性**：配置即环境、统一响应包、清晰分层、迁移幂等、优雅降级。

---

## 13. 已知约束与后续

- 本仓库限流为内存实现，多副本需改 Redis。
- 媒体为本地卷，横向扩展需换对象存储（S3/OSS）并改 `MEDIA_ROOT`/上传逻辑。
- 评论审核、反垃圾为规则引擎，可后续接模型打分。
- 监控/告警未内置，建议接 Prometheus + Grafana 或云厂商 APM。
